## P2 — Nên sửa trong step 2

### R7. `selfMergeEligible` kiểm 1 run, tài liệu hứa 2 run liên tiếp

### R8. Triage weights: code, policy và tài liệu lệch nhau
- Code: protectedPathHit là binary (có hit = +20, 5 hit cũng +20). Tài liệu mục 3 ghi `20*protectedPathHits (cap 20)` — đọc kiểu nào cũng lệch code.
- Code: `newDependency` weight 10 × min(3) = tối đa +30; tài liệu ghi `10*min(newDependencies,3)` khớp code nhưng mâu thuẫn trực giác "mỗi dependency +10" — nên ghi rõ cap.
- Weights trong policy file bị bỏ qua hoàn toàn (xem R1). Sau R1, thêm test: đổi weight trong policy phải đổi triagePriority.

### R9. `packagesTouched` chưa phải monorepo package
`count_packages_touched` lấy 2 components đầu của path; file ở root (`app.py`) cũng thành 1 "package", `schema/x.json` thành package `schema`. Đây là *thư mục chạm vào*, không phải package theo package.json/workspace/pom. Case #44 (package mục dần theo history) dùng số này sẽ sai. Đổi tên counter thành `topDirsTouched` cho trung thực, hoặc detect package thật qua manifest — chọn tên đúng trước khi có consumer dùng số này.

### R10. `count_unresolved_symbols` mong manh ngoài môi trường test
- Chỉ quét `*.py`; TypeScript (knip/tsc trong SPEC) chưa có — chấp nhận được cho step 1 nếu nói rõ, nhưng skill/README không ghi giới hạn này ở chỗ người dùng chạy.
- Phụ thuộc `ruff` có trên PATH: thiếu ruff là crash `FileNotFoundError` (đã tái hiện khi chạy pytest không có venv trên PATH), không phải verdict. Gate không được crash thay vì phán: bắt lỗi tool, trả finding `toolMissing` + BLOCK hoặc exit code riêng.
- Quét file theo working tree hiện tại, không checkout head SHA: chạy gate từ checkout khác base/head sẽ cho kết quả của cây sai. CLI nên tự tạo worktree theo head hoặc từ chối nếu `git rev-parse HEAD != head`.

### R11. Counters "0 = chưa chạy" chưa có biểu diễn cho máy
`deadCodeCandidates, newPublicSymbols, unmappedClaims, redundantCommentLines, layerContractViolations, nondeterministicDiffLines...` đều emit 0 dù chưa wire. Chỉ renderer (cho người) nói notRun, và chỉ nói 2 mục. Consumer máy không phân biệt được 0-đo-được và 0-chưa-chạy. Đây là cùng gốc với R2: cần `gatesRun/gatesNotRun` hoặc `counterStatus` trong schema trước khi có consumer ngoài.

### R12. `tests` object luôn false/0 nhưng mang tên như đã chạy
`redOnBase:false, greenOnHead:false, changedLinesCoveredPercent:0` trong mọi verdict. Máy đọc sẽ hiểu "test đỏ trên head" thay vì "chưa chạy test". Cùng fix với R11: đánh dấu notRun, đừng để false giả danh kết quả.

### R13. Diff parsing sẽ vỡ ở rename/binary/tên file lạ
- `collect_diff_scope`: `line.split("\t", 2)` giả định numstat luôn 3 cột sạch; git quote path có ký tự đặc biệt (dấu ngoặc kép/octal) sẽ cho path sai -> protectedPathHits có thể bị lách bằng tên file có ký tự đặc biệt. Dùng `git diff --numstat -z` và parse theo NUL.
- `_added_lines` dựa vào `+++ b/` — file mới ở thư mục có prefix lạ hoặc rename sẽ lệch; secret scan có thể sót dòng ở file rename. Dùng `--unified=0 -z` hoặc parse theo từng file block.
